HDMIRXTEST V1.1.2 — SIMPLE CUSTOM-EDID TUTORIAL
================================================
Repository: https://github.com/N0tiK44/hdmirxtest
Orange Pi: visionseek@192.168.20.35

IMPORTANT
---------
Use Windows EXTEND THESE DISPLAYS for this experiment.
Do not use Duplicate. Duplicate mode can borrow the MSI's 240-Hz mode and does
not prove that the Orange Pi HDMI-RX EDID supports it.


1. FIRST TIME ONLY — ORANGE PI
==============================
SSH into the Orange Pi and run:

    mkdir -p ~/src
    cd ~/src
    git clone https://github.com/N0tiK44/hdmirxtest.git
    cd hdmirxtest
    bash scripts/install-deps.sh


2. NORMAL 1080P60 BASELINE
==========================
On the Orange Pi:

    cd ~/src/hdmirxtest
    bash scripts/pi-cycle.sh baseline

Result:

    ~/hdmirxtest-baseline-latest.tar.gz

Windows PowerShell copy command:

    scp visionseek@192.168.20.35:~/hdmirxtest-baseline-latest.tar.gz "$env:USERPROFILE\Downloads\hdmirxtest-baseline-latest.tar.gz"


3. CUSTOM 1080P240 EDID — EASIEST METHOD
========================================
On the Windows copy of the repo, double-click:

    RUN-240-WIZARD.cmd

The wizard will:

    1. update the Pi from GitHub
    2. save the current RK-UHD EDID permanently
    3. validate the bundled custom EDID
    4. load RK-1080P240 into the Orange Pi HDMI-RX
    5. read the EDID back and compare every byte
    6. pause for the Windows display change

At the pause, use Windows 11:

    Settings
      -> System
      -> Display
      -> Extend these displays
      -> select RK-1080P240
      -> Advanced display
      -> 1920 x 1080
      -> 240 Hz

Use 8-bit SDR. Leave HDR and VRR off.

If Windows still shows RK-UHD or only 60 Hz, disable/re-enable Display 2 or
unplug/replug the CPU/iGPU HDMI cable. This forces Windows to read the new EDID.

Return to the wizard and press ENTER. It will probe the real HDMI-RX timing and
only start the full 240-Hz passthrough test if the Pi reports approximately
1920x1080 at 240 fps.

Expected result files in Windows Downloads:

    hdmirxtest-prepare240-latest.tar.gz
    hdmirxtest-240-latest.tar.gz

Send both files back for review. The Pi also keeps a compatibility copy named
hdmirxtest-latest.tar.gz.


4. MANUAL 240-HZ METHOD
=======================
Load and verify the custom EDID:

    cd ~/src/hdmirxtest
    bash scripts/pi-cycle.sh prepare240

Change Windows to extended 1920x1080 at 240 Hz as described above.

Probe only:

    cd ~/src/hdmirxtest
    bash scripts/pi-cycle.sh probe240

If the probe confirms 1080p240, run the full test:

    cd ~/src/hdmirxtest
    bash scripts/pi-cycle.sh 240

Manual Windows copy commands:

    scp visionseek@192.168.20.35:~/hdmirxtest-prepare240-latest.tar.gz "$env:USERPROFILE\Downloads\hdmirxtest-prepare240-latest.tar.gz"

    scp visionseek@192.168.20.35:~/hdmirxtest-probe240-latest.tar.gz "$env:USERPROFILE\Downloads\hdmirxtest-probe240-latest.tar.gz"

    scp visionseek@192.168.20.35:~/hdmirxtest-240-latest.tar.gz "$env:USERPROFILE\Downloads\hdmirxtest-240-latest.tar.gz"


5. EMERGENCY EDID RESTORE
=========================
If Windows rejects the EDID, the screen stays black, or you simply want the
original RK-UHD profile back, double-click on Windows:

    RUN-RESTORE-EDID.cmd

Or run on the Orange Pi over SSH:

    cd ~/src/hdmirxtest
    bash scripts/pi-cycle.sh restoreedid

Then disable/re-enable Display 2 or replug the CPU/iGPU HDMI cable.

The restore command prefers the permanent EDID captured immediately before the
custom profile was first loaded. A verified stock RK-UHD EDID is also bundled
as a final recovery fallback.
