# V1.2.0 — automatic bridge EDID and fast live start

## Added

- Reads the EDID from the single connected HDMI-TX monitor.
- Generates and byte-verifies a 256-byte HDMI-RX clone.
- Hard ceiling: width <= 1920, height <= 1080, refresh <= 240.25 Hz, pixel
  clock <= 600 MHz.
- Keeps established, standard, CTA VIC, and detailed timings only when their
  geometry/rate is understood and inside the ceiling.
- Unknown timing-bearing blocks fail closed.
- Promotes the highest safe detailed timing, so the captured Zowie profile
  again prefers its genuine 571-MHz 1080p239.964 timing.
- Advertises RGB 8-bit SDR by clearing YCbCr, deep-colour, HDR, 4:2:0, VRR,
  FRL, DSC, and unknown vendor-video capability blocks.
- Reads the live V4L2 DV timing inside the C program and automatically selects
  the nearest identical-resolution DRM connector mode.
- Refuses capture above the 1080p240 ceiling even if a bad EDID/source bypasses
  negotiation.
- Subscribes to HDMI-RX source-change events and asks the wrapper to rematch
  safely after a Windows timing change.

## Fast path

`bash scripts/pi-cycle.sh 240` no longer fetches Git, runs a clean rebuild,
collects a pre-run debug bundle, or launches a separate 240-Hz probe. It uses
an existing up-to-date binary, or performs only the necessary incremental
build, then starts the proven DMA-BUF pipeline.

Repository updates are explicit with `bash scripts/pi-cycle.sh sync`, or can be
combined with a run using `SYNC=1 bash scripts/pi-cycle.sh 240`.

## Native colour paths

- RGB 8-bit source: V4L2 `BGR3` -> DRM `RGB888` (`RG24`)
- YUV444 fallback: V4L2 `NV24` -> DRM `NV24`

Both remain direct DMA-BUF imports. No CPU conversion or copy was added.
