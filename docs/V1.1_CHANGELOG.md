# V1.1 experimental lab build

## V1.1.2 custom EDID

- added `edid/rk1080p240.bin`, derived from the captured Zowie XL2546X EDID
- made the Zowie's real 571-MHz 1920×1080@239.964 timing preferred
- retained 1920×1080@60 as the first fallback
- added checksum/timing validation and byte-for-byte RX EDID read-back
- added permanent pre-change backup and verified restore mode
- added `RUN-RESTORE-EDID.cmd`
- fixed sysfs EDID collection for zero-size pseudo-files
- changed results to mode-specific archives so debug cannot overwrite baseline
- documented that Windows must use extended rather than duplicated displays

V1.1 is deliberately conservative: the hardware-verified V1.0 zero-copy/fence/ownership path is retained. The only change in the C critical path is high-refresh EDID mode matching so fractional rates such as 239.760 Hz can satisfy a 240.000-Hz experimental target without relaxing the strict 59.940-vs-60.000 rule.

## Added

- `scripts/pi-cycle.sh` — safe Git sync, build, test, debug collection and result packaging.
- `tools/host-cycle.ps1` — Windows-host orchestration over SSH/SCP.
- `RUN-240-WIZARD.cmd` — prepare EDID, pause for the Windows mode change, then run the gated 240-Hz diagnostic.
- `scripts/prepare-240.sh` — backs up HDMI-RX EDID and loads the validated custom 1080p240 profile.
- `scripts/probe-240.sh` — refuses the full test unless HDMI-RX reports 1920×1080 at roughly 240 fps; it then locks the detected DV timing and requests NV24.
- `scripts/collect-debug.sh` — captures V4L2 timings, EDIDs, DRM/KMS state, debugfs state, kernel messages and Git state.
- `scripts/restore-rx-edid.sh` — restores and verifies the permanent pre-change HDMI-RX EDID.
- apt/apk dependency bootstrap and one-click Windows launchers.

## Git/update behavior

The old V1.0 updater stopped whenever the SBC worktree was dirty. V1.1 instead stashes uncommitted changes automatically before deployment, preserves divergent committed work on a timestamped backup branch, and resets the SBC deployment checkout to `origin/main`.

## Experimental status

1080p240 on RK3588 HDMI-RX is **not yet claimed as supported**. This build is intended to answer that question on the actual Orange Pi 5 Plus and Zowie hardware while preserving a complete debug archive whether the gate passes or fails.
