# V1.2.3 — continuous operation, systemd persistence and faster rematch

- `live` and `240` run continuously by default. A finite duration is now an
  explicit diagnostic choice (`DURATION=120`).
- Ubuntu/systemd receives verified boot-time EDID loading and a persistent
  zero-copy passthrough service with automatic source-wait/restart behavior.
- A normal HDMI-RX timing change disables only the active scanout plane and
  keeps the current connector/CRTC mode alive while the next timing is
  matched. It no longer restores the original 60-Hz mode between changes.
- Setup stops an existing persistent service before the EDID transaction and
  enables both systemd units without starting passthrough before the source is
  reconnected.
- `service-start`, `service-stop` and `service-status` are available through
  `scripts/pi-cycle.sh`.
- Setup result archives now contain the audit manifest, source EDID, bridge
  EDID, hashes and recovery EDID instead of only the console log.
- Monitor identity and capability filtering remain unchanged from V1.2.2.
