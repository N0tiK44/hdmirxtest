HDMIRXTEST V1.2.3 — PERSISTENT IDENTITY CLONE + FAST LIVE VIDEO
=============================================================

IMPORTANT
---------
Use Windows EXTEND THESE DISPLAYS. Do not use Duplicate.
Run every project command below on the Orange Pi.


1. INSTALL ONCE
===============

    mkdir -p ~/src
    cd ~/src
    git clone https://github.com/N0tiK44/hdmirxtest.git
    cd hdmirxtest
    bash scripts/install-deps.sh


2. CLONE THE MONITOR EDID ONCE
==============================

    cd ~/src/hdmirxtest
    bash scripts/pi-cycle.sh setup

PHYSICALLY UNPLUG WINDOWS FROM HDMI-RX FIRST. The Pi reads the EDID of the real
monitor connected to HDMI-TX, removes every
unproven mode above 1920x1080 or 240 Hz, removes HDR/deep-colour/YUV/VRR
advertisement, and installs the verified RGB 8-bit clone into HDMI-RX.

Physically unplug/replug the Windows-to-Pi HDMI cable once, or disable/re-enable
that Windows display. Keep Windows in Extend mode, then select any advertised
refresh rate.


3. START PERMANENT VIDEO (UBUNTU/SYSTEMD)
=========================================

    cd ~/src/hdmirxtest
    bash scripts/pi-cycle.sh service-start

The service keeps running after the SSH session closes and starts automatically
on later Pi boots. Useful controls:

    bash scripts/pi-cycle.sh service-status
    bash scripts/pi-cycle.sh service-stop

For a foreground run instead:

    bash scripts/pi-cycle.sh 240

The legacy `240` name now starts automatic timing match. It does not run Git,
a clean rebuild, a separate probe, or a pre-run debug dump, so repeat starts
reach video as quickly as the driver and monitor can lock. It runs continuously
until Ctrl-C; use `DURATION=120 bash scripts/pi-cycle.sh 240` for a timed test.

V1.2.3 accepts either native source format:

    RGB888 source  -> V4L2 BGR3 -> DRM RGB888/RG24
    YUV444 source  -> V4L2 NV24 -> DRM NV24

Both are direct DMA-BUF zero-copy paths. There is no GStreamer, CPU colour
conversion, framebuffer copy, or deliberate extra frame queue.

After a timed/foreground run ends, its result is:

    ~/hdmirxtest-240-latest.tar.gz


4. EMERGENCY RESTORE
====================

    cd ~/src/hdmirxtest
    # Unplug Windows from HDMI-RX first
    bash scripts/pi-cycle.sh restoreedid

Recovery installs an audited RGB 8-bit 1080p60 EDID. It does not restore the
old stock/original EDID or any unaudited historical backup.

Then physically reconnect the Windows-source HDMI cable.


5. UPDATE OR RUN DIAGNOSTICS
============================

    bash scripts/pi-cycle.sh sync
    bash scripts/pi-cycle.sh diagnostic
    bash scripts/pi-cycle.sh baseline
    bash scripts/pi-cycle.sh debug

Results:

    ~/hdmirxtest-baseline-latest.tar.gz
    ~/hdmirxtest-debug-latest.tar.gz
